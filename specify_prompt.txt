Build SFinance, a personal finance desktop application. The app helps a single
user track income and expenses, understand spending patterns over time, and
manage recurring subscriptions and financing — all with data stored entirely
on-device.

## Categories

Categories are fixed and predefined. The user cannot create, edit, or delete
them. They are split by transaction type:

**Expense categories:**
- Producto — one-off purchase of a physical item (e.g. a laptop)
- Servicio — one-off service consumption (e.g. dining out)
- Suscripción — recurring subscription (e.g. Claude Pro)
- Suministro variable — variable utility bill (e.g. electricity)
- Financiación — instalment financing (e.g. a car purchase plan)

**Income categories:**
- Salario — employment salary (12 or 14 payments per year)
- Venta — one-off sale of an item (e.g. selling a laptop)
- Servicio — one-off income from a service rendered (e.g. freelance work)

## Transaction Entry Forms

### "+ Gasto" modal (expense)

Fields always shown:
- Nombre (text, required)
- Monto (numeric, required; positive value)
- Descripción (optional text)
- Categoría (dropdown; predefined expense categories)

Additional fields shown **only** when category is **Suscripción or Financiación**:
- Periodicidad (dropdown: Mensual / Anual)
- Fecha de fin:
  - If Periodicidad = Mensual → picker selects a month within a year
    (e.g. "Octubre de 2027")
  - If Periodicidad = Anual → picker selects a year only (e.g. "2029")
  - Always required; there are no open-ended recurrences

For all other expense categories (Producto, Servicio, Suministro variable),
no recurrence fields appear. These are always one-off entries.

### "+ Ingreso" modal (income)

Fields always shown:
- Nombre (text, required)
- Monto (numeric, required; positive value)
- Descripción (optional text)
- Categoría (dropdown; predefined income categories)

Additional fields shown **only** when category is **Salario**:
- Número de pagas (dropdown: 12 pagas / 14 pagas)
- If 14 pagas is selected → two month pickers appear, labeled
  "Primera paga extra" and "Segunda paga extra", for the user to choose
  which two months receive the extra payment. Each extra payment equals
  the full monthly salary amount.

For Venta and Servicio income categories, no additional fields appear.

## Recurring Entries — Generation Rules

For Suscripción and Financiación expenses, and for Salario income:
- Individual transaction entries are generated for each recurrence period
  from the start date up to today (or the end date, whichever comes first).
- Future occurrences are never pre-generated; they are created on app launch
  when their date has arrived.
- Generated entries appear in lists and charts identically to one-off
  transactions. No special visual distinction is required in this version.
- For 14-paga salaries, the two extra-payment months generate an additional
  entry of the same amount as the regular monthly entry.

## Core Views

The app has three main views accessible via a top navigation bar.

### View 1 — Resumen (default on launch)

- Top KPI strip: three cards —
  - Ingresos: total income for the current month (green)
  - Gastos: total expenses for the current month (red)
  - Balance: lifetime total (all-time income minus all-time expenses), shown
    in an accent color. This card is editable: tapping/clicking it opens an
    inline field where the user can set an initial capital amount. That value
    is added to the calculated balance and persisted. As soon as the user
    records their first transaction, the initial capital is discarded and the
    balance becomes purely calculated from that point forward. The editable
    state is only available before any transaction exists.
  Values always show currency symbol, locale-aware formatting, and explicit
  sign (+ / −). Color is never the sole indicator of direction.
- "Resumen Mensual" grouped bar chart: income (green) vs. expenses (red)
  per month, showing the last few months.
- "Transacciones Recientes" list: most recent transactions, each row showing
  a colored icon, transaction name, category + date, and signed amount.

### View 2 — Análisis

- Same top KPI strip as Resumen.
- Three stacked line charts:
  - "Evolución del Balance" (blue line)
  - "Evolución de Gastos" (red line)
  - "Evolución de Ingresos" (green line)
- Each chart has an independent time range selector (top-right). Options:
  - Últimos 7 días (default)
  - Último mes
  - Últimos 3 meses
  - Último año
  - Desde origen

### View 3 — Entradas

- "Transacciones" list with a time range filter (same five options as above;
  default: Últimos 7 días).
- All transactions matching the selected range, ordered most recent first.
- Same row layout as the recent transactions list in Resumen.

## Financial Accuracy

- All monetary values are stored and calculated in integer cents to avoid
  floating-point errors.
- Currency symbol is always €. Formatting is locale-aware.
- Positive amounts (income) always display as +€X,XX in green.
- Negative amounts (expenses) always display as −€X,XX in red.
  Both sign and color are used simultaneously; color is never the sole
  indicator of direction.
- Balance is always computed as total income minus total expenses for the
  relevant period; it is never stored as a cached derived value.
-  The KPI cards for Ingresos and Gastos always reflect the current calendar
     month only, not all-time totals.
-   The Balance KPI always reflects the all-time total (desde origen), computed
    as lifetime income minus lifetime expenses, plus the initial capital if no
    transactions have been recorded yet.
-   Initial capital is stored as a single on-device value, separate from the
    transactions ledger. It is automatically cleared the moment the first
    transaction is saved. It cannot be restored or edited after that point.

## Data & Privacy

- All data is stored on-device only.
- No network calls, no sync, no telemetry, no analytics.
- The app must function fully offline at all times.

## UX & Accessibility

- Dark theme throughout, as shown in the mockups.
- All interactive elements must be keyboard-navigable.
- Color contrast must meet WCAG AA minimum.
- No hover-only or right-click-only interactions as primary affordances;
  all actions must have a touch-compatible equivalent in anticipation of
  the planned Android version.
